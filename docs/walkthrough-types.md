   Scenario ids `S1`..`S24`, `T4`..`T21` below refer to these.

   `probe/Fuzz.cs`, `probe/Fuzz2.cs`). Three Yjs clients edit concurrently; every step that touches
   the observed client (a local transaction of 1-4 operations, or a remote update) is recorded with

## Findings

Ordered by severity. "Fix validated" means the fix is in `/tmp/ycs-walk-b/validated-fixes.patch`
and the trace sets are equal with it.

### 1. `YTextEvent.Delta`: every insert after the first repeats the earlier inserts (wrong event)

`src/Ycs/Types/YText.cs`, `addOp`, case `Insert`: Yjs resets `insert = ''` after emitting the op;
the port does not. The next inserted run is appended to the previous value, and when the previous
value was an embed, to its `ToString()`.

- Scenario S1: text `xyz`; one transaction `insert(0,'a'); insert(2,'b')`.
  Yjs: `[{insert:'a'},{retain:1},{insert:'b'}]`. Port: `[{insert:'a'},{retain:1},{insert:'ab'}]`.
- Scenario S2: text `x`; `insertEmbed(0,{img:1}); insert(2,'b')`.
  Yjs: `[{insert:{img:1}},{retain:1},{insert:'b'}]`. Port: last op is
  ``{insert:"System.Collections.Generic.Dictionary`2[System.String,System.Object]b"}``.
- Also whenever one transaction or one remote update inserts text with two different attribute sets
  (`[bold a][plain b]` gives `a`, then `ab`).
- Confirmed by run. An editor binding that applies the delta shows wrong text.
- Fix validated: `insert = string.Empty;` after the op is built.

### 2. `YTextEvent.Delta`: formatting branch still has the Yjs 13.4 logic, and deletes in the wrong transaction (wrong event, wrong bytes)

Three differences in the `ContentFormat` case:

a. Format item that existed before and is not deleted, while `attributes[key]` is set and differs:
   Yjs 13.6: `value === null ? delete attributes[key] : attributes[key] = value`. Port: the reverse
   (`null` sets `attributes[key] = null`, a value removes the key).
b. Yjs deletes a redundant format only `else if (value !== null)` (added item) and
   `else if (attr !== null)` (existing item). The port deletes in both cases without the guard.
c. Yjs deletes with the transaction of its inner `transact` (a new one: a second update and a
   second event follow). The port passes `Transaction`, the event's own transaction, whose delete
   set was already sorted and whose observers are running: the deletes land in the finished
   transaction's update, no second event fires, and the delete set is no longer sorted while
   `Deletes()` keeps doing binary searches on it.

- Scenario S18: A and B have `abcd`. A: `format(0,4,{bold:true})`. B: `format(1,2,{bold:true})`.
  O has B's state, observes, applies A's update.
  Yjs: events `[{retain:3,attributes:{bold:true}}]` and `[]`; state keeps A's trailing `bold:null`.
  Port: one event `[{retain:3,attributes:{bold:true}},{retain:1,attributes:{bold:null}}]`; the
  trailing `bold:null` item is deleted and collected, so the state bytes differ from Yjs.
- In the observed text traces: 1,225 steps with a wrong delta, 63 with different state bytes, 8 with
  a different `toDelta()` segmentation. The visible text and formatting stayed equal in all of them.
- Confirmed by run. Fix validated: the 13.6.32 branch, the two guards, `item.Delete(transaction)`.

### 3. Deep observers: `CurrentTarget` and `Path` are wrong unless the observed type is the last ancestor (wrong event)

Yjs sets `event.currentTarget = type` only for types that have a deep observer. The port sets it for
every entry of `ChangedParentTypes`, so an event ends with the last type of the dictionary.

- Scenario S5: root map `r` > map `mid` > array `leaf`; `mid.observeDeep`; `leaf.push([1])`.
  Yjs: `currentTarget === mid`, `path = ['leaf']`. Port: `CurrentTarget == r`, `Path = ['mid','leaf']`.
- Scenario S7: deep observer on the root only, 40 child arrays changed in one transaction.
  Yjs: every path is `['kN']`. Port: `Path` is empty for 39 of the 40 events (each got its own
  target as current target after the root was processed).
- Scenario S5b: no deep observer at all, event read in `AfterTransaction`:
  Yjs `currentTarget === target`, `path = []`; port `CurrentTarget == root`.
- 947 steps of the array/map traces. Confirmed by run.
- Fix validated: test `DeepEventHandler != null` before touching the events (needs an accessor on
  `AbstractType`).

### 4. Deep observers: events of equal path length arrive in a different order (wrong order)

`List<T>.Sort` is unstable above 16 elements; `Array.prototype.sort` is stable.

- Scenario S7b (41 events): Yjs `root, k0, k7, k14, ...` (order of change); port
  `root, k34, k1, k8, ..., k13, k0`.
- Confirmed by run. Fix validated: a stable sort (`OrderBy`, or an insertion sort on the copy).

### 5. Observers are called in a different order after a changed type was deleted in the same transaction (wrong order)

`ContentType.Delete` removes the type from `Transaction._changed`, a `Dictionary`. The next added
key reuses the freed slot, so enumeration is no longer insertion order; a JS `Map` keeps it.

- Scenario S6: roots `A`, `P` (map, holding array `B`), `C`. One transaction:
  `A.push; B.push; P.delete('b'); C.push`. Yjs calls `A, P, C`; the port `A, C, P`.
- 25 steps of the array/map traces. Confirmed by run.
- Fix validated: an insertion-ordered dictionary for `_changed` (`OrderedDictionary<,>`; its
  `Remove` is O(n), acceptable here, or a tombstone).

### 6. Deep observers receive events whose target was deleted meanwhile (wrong event)

Yjs filters `events` to those whose target is not deleted before calling the deep observer. The
port only skips setting `CurrentTarget` for them and still delivers them.

- Scenario S16: root map with arrays `x`, `y`; `x.observe(() => root.delete('y'))`;
  `root.observeDeep`; one transaction `y.push; x.push`. Yjs delivers 1 event, the port 2.
- Confirmed by run. Fix validated (filter into the copy that is sorted).

### 7. `YArray.Push`/`Add` is `Insert(Length)`, not `typeListPushGenerics` (wrong bytes)

Yjs appends after the last item of the list, deleted ones included (origin = that item, no right
origin). The port inserts after the last visible item (right origin = the first trailing deleted
item).

- Scenario S3: `insert(0,[1,2]); delete(1,1); push([3])`.
  Yjs item: info `0x88`, origin `(1,1)`. Port: info `0xc8`, origin `(1,0)`, right origin `(1,1)`.
  T5: `insert(0,[1]); delete(0,1); push([2])`: Yjs `0x88`, port `0x48`.
- Both are valid and every peer converges, but the bytes differ from Yjs and the position relative
  to concurrent inserts after the deleted tail can differ from what a Yjs peer would have produced.
  139 of 300 traces. `YXmlFragment.Push` is `insert(length)` in Yjs too and is identical.
- Confirmed by run. Fix validated: `PushGenerics` (marker with the highest index, walk right,
  `InsertGenericsAfter`; no marker update).

### 8. Deleted and collected structs are merged less than in 13.6.32 (wrong bytes; outside area B)

`DeleteSet.TryToMergeWithLeft` is the 13.4 single merge. 13.6.32 has `tryToMergeWithLefts`, which
keeps merging to the left, skips what it merged, and walks `_mergeStructs` from the end with a
`continue` when more than one struct was merged.

- Trace 226 of `trace2-nopush.json` (three local transactions on roots `m`, `a`):
  1. `a.insert(0,['a', new Y.Map([['k2','a']]), 'b'])`; `a.get(1).set('k2', new Y.Map([['k3',{x:1}]]))`;
     `a.get(1).set('k2',[1,2])`; `m.delete('k2')`
  2. `m.set('k1','b')`; `a.get(1).delete('k2')`
  3. `a.delete(1,2)`; `a.insert(0,[{x:1},1])`; `a.delete(0,2)`

  Yjs ends with 7 structs, one `GC` of length 3. The port has 8: `GC` 1 and `GC` 2.
- 10 of 300 array/map traces; none in the text traces. Content is unaffected.
- Confirmed by run. Fix validated: `TryToMergeWithLefts` and the three loops as in 13.6.32.

### 9. `Insert` beyond the length inserts at the front instead of throwing (wrong document)

`typeListInsertGenerics` throws "Length exceeded!" when `index > length`. `InsertGenerics` has no
check: the walk ends with `n == null` and `InsertGenericsAfter(null)` puts the content first.

- Scenario S4: `a.insert(0,[1,2]); a.insert(5,[9])`. Yjs throws. Port: `[9,1,2]`.
- Applies to `YArray.Insert` and `YXmlFragment.Insert`. Confirmed by run.
- Fix: `if (index > Length) throw` at the top of `InsertGenerics` (before any change).

### 10. A shared type inside a text is invisible to `ToDelta` and to the event delta, and cannot be inserted (wrong event, wrong read, API gap)

Yjs treats `ContentType` like `ContentEmbed` in `toDelta` and in `YTextEvent#delta`, and
`insertText` wraps an `AbstractType` in `ContentType`. The port handles `ContentEmbed` only and
wraps everything that is not a string in `ContentEmbed`.

- Scenario S10: Yjs peer does `t.insertEmbed(1, new Y.Map()); t.insert(3,'c')` on `ab`; the port
  applies the update. Yjs: `toDelta = [{insert:'a'},{insert:<YMap>},{insert:'bc'}]`, event
  `[{retain:1},{insert:<YMap>},{retain:1},{insert:'c'}]`. Port: `toDelta = [{insert:'abc'}]` while
  `Length` is 4, event `[{retain:2},{insert:'c'}]`: every later index of a binding is off by one.
- `t.InsertEmbed(1, new YMap())` throws `NotSupportedException` (S10local), after the transaction
  started. `Clone` of such a text loses the type.
- Confirmed by run. Fix: `case ContentType` next to `ContentEmbed` in `ToDelta` and `Delta` (the
  latter validated), and `text is AbstractType ? new ContentType(...)` with `CheckCanNest` in `InsertText`.

### 11. `Keys`/`Changes` read after the transaction's GC throw `NotImplementedException` (exception)

`AfterTransactionCleanup`, `Update` and `UpdateV2` handlers run after GC and before the transaction
ends, so an event may still be read there. Yjs returns `oldValue: undefined` for collected content
(`array.last([])`). The port calls `ContentDeleted.GetContent()`, which throws.

- Scenario T4: `m.set('k',1)`; observer keeps the event; `AfterTransactionCleanup` reads
  `ev.Keys`; `m.set('k',2)`. Yjs: `[['k',{action:'update',oldValue:undefined}]]`. Port: throws.
- The same `GetContent()` is reached by `TypeMapGetSnapshot`/`GetAllSnapshot`/`GetAttributes(snapshot)`
  for a value that was collected (a document with GC on); Yjs returns `undefined` there.
- Confirmed by run (T4); the snapshot case by reading.
- Fix: `ContentDeleted.GetContent()` returns an empty list as in Yjs, and `CollectKeys` uses
  `LastOrDefault()`.

### 12. A throwing observer stops the other observers of the same type (wrong event)

`callEventHandlerListeners` uses `callAll`: every listener runs, then the error propagates. A
multicast delegate stops at the first exception.

- Scenario S8: two observers on one array, the first throws. Yjs calls both (`[1,2,'thrown']`), the
  port only the first (`[1,'thrown']`). Same for deep observers and the document events.
- Also: with several throwing callbacks Yjs propagates the last error, the port the first (cosmetic).
- Confirmed by run. Fix: invoke `GetInvocationList()` one by one in `InvokeEventHandlers` and
  `CallDeepEventHandlerListeners`, keep the first exception.

### 13. `YTextEvent.Changes` is the list-style change set (wrong event)

Yjs overrides `changes` for text: `{keys, delta: this.delta, added: empty, deleted: empty}`. The
port inherits `YEvent.Changes`.

- Scenario S9: `xyz`; `insert(1,'a'); delete(3,1)`. Yjs `changes.delta =
  [{retain:1},{insert:'a'},{retain:1},{delete:1}]`, `added.size = 0`, `deleted.size = 0`. Port:
  `Insert` is a list of boxed `char`s (`['a']`), `Added.Count = 1`, `Deleted.Count = 1`, and formats
  count as retained items.
- Confirmed by run. Fix: make `Changes` virtual and override it in `YTextEvent`.

### 14. `ToDelta(snapshot, prevSnapshot, computeYChange)` compares `State` where Yjs compares `type` (wrong read)

`cur.type !== 'removed'` became `cur.State != YTextChangeType.Removed`. `State` is a second
property that neither the default nor a caller's `computeYChange` has a reason to set, so it stays
`Added`.

- Scenario T8b: `computeYChange` returns `{Type, User}`. Yjs: `[bc removed by 1][X added by 1]`.
  Port: `[bcX removed by 1]`: the added `X` is reported as removed.
- `User` is an `int`, client ids are up to 2^32-1: a `(int)` cast in the caller wraps, and
  `cur.User != n.Id.Client` then never matches (more ops than Yjs, same content).
- Without `computeYChange` the output equals Yjs (T8a, T8c).
- Confirmed by run. Fix: compare `Type`; drop `State`; make `User` a `long`.

### 15. `ToDelta()` always opens a transaction, and throws on a text outside a document (wrong event, exception)

Yjs transacts only when a snapshot is given. The port always does (origin
`"splitSnapshotAffectedStructs"`, Yjs uses `'cleanup'`).

- Scenario S15: `AfterTransaction` handler, then `t.ToDelta()`: Yjs fires 0 times, the port once
  (also `BeforeTransaction`, `BeforeAllTransactions`, `AfterAllTransactions`). `YXmlText.ToString()`,
  `YXmlFragment.ToString()` with text children, `Clone()` and `ToJson()` of XML go through it.
- T17-T19: `new YText("abc").ToDelta()`, `new YXmlText("abc").ToString()` and
  `new YText("abc").Clone()` throw `NullReferenceException`; Yjs returns `[]`, `''` and an empty clone.
- Confirmed by run. Fix: run `computeDelta` directly when both snapshots are null (and `Doc` may be
  null then).

### 16. Events exist only when observed at that moment (wrong event, rare)

`IsObserved` is evaluated when the type's turn comes. Yjs always creates the event and fills
`changedParentTypes`.

- Scenario T10: `x` (no observer) and `y` change in one transaction; `y`'s observer attaches a deep
  observer to the root. Yjs calls it with 2 events, the port with 1 (the event of `x` was never made).
- `transaction.ChangedParentTypes` is empty for a caller that only listens to `Update`/`UpdateV2`/
  `BeforeObserverCalls` (they are not in `HasTransactionListeners`).
- Confirmed by run (T10). Accept and document, or fall back to creating events once any observer
  was attached during the cleanup.

### 18. XML string forms (cosmetic)

- `GetAttributes(snapshot)` drops attributes whose value is `null`; Yjs keeps them (T7:
  `{n:null,s:'v'}` against `{s:'v'}`). Confirmed by run.
- `YXmlElement.ToString()` formats non-string values with .NET rules and the current culture: `True`
  for `true` (T15, confirmed by run), `1,5` for `1.5` under a comma culture (by reading; the analyzer
  flags the same pattern elsewhere as CA1305). Fix: format through the JSON writer or invariant culture.
- `YXmlText.ToString()`: a format whose value is a string renders in Yjs as indexed attributes
  (`<color 0="r" 1="e" 2="d">`, a quirk of `for..in` over a string); the port renders `<color>`. An
  embed renders as `[object Object]` in Yjs. A `YXmlHook` child of a fragment renders as
  `[object Object]` in Yjs and as the type name in the port. By reading.

### 19. `FindMarker`: integer division (performance, cosmetic)

`Math.Abs(marker.Index - pIndex) < Length / MaxSearchMarkers` divides integers; Yjs divides floats.
For a length below 80 the right side is 0 and an existing marker is never adjusted (Yjs adjusts it
when the distance is 0); between multiples of 80 the threshold is lower than in Yjs. The port
creates more markers (bounded by 80) and reuses fewer. No document difference in 4,309 marker-heavy
steps. Markers only matter for the content in one corner both implementations share: a root text
that received formats while it was still an untyped placeholder keeps its markers enabled
(`_hasFormatting` and `_searchMarker = null` are set on the placeholder and lost in `doc.get`), and
there the marker chosen decides which attributes `deleteText` sees. By reading.
Fix: `Length / (double)MaxSearchMarkers`.

### 20. Small differences (cosmetic, by reading)

a. `EqualAttrs`: Yjs' `equalFlat` compares own enumerable keys, so `[]` equals `{}`, `[1,2]`
   equals `{0:1,1:2}`, and two `Uint8Array`s with the same bytes are equal. The port compares
   dictionary with dictionary and list with list; two `byte[]` are equal only when empty (`byte` is
   not in `TryGetNumber`). `decimal`, `byte`, `sbyte`, `ushort` are not numbers for `StrictEquals`.
b. `insertAttributes` iterates `for (const key in attributes)`: integer-like keys first, ascending.
   The port iterates the caller's dictionary. A format map with keys like `"1"` and `"a"` yields
   the format items in a different order (different bytes, same formatting).
c. Unobserving a handler that was registered twice removes both in Yjs, one in the port; removing
   an unknown handler logs an error in Yjs.
d. A pending `applyDelta(delta, {sanitize:false})` loses the option in Yjs (replayed as
   `applyDelta(delta)`); the port keeps it. Here the port is the correct one.
e. `typeListInsertGenericsAfter` copies a `Uint8Array` (`new Uint8Array(c)`); the port stores the
   caller's `byte[]`: mutating it afterwards changes the document without a transaction. `map.set`
   does not copy in Yjs either.
f. `ContentString.GetContent()` yields `char`s, Yjs one-character strings (visible through
   `Changes.Delta` and `Slice` on text only).

### 21. Observations that are equal, for the record

- The formatting cleanup ported from 13.6.32 (`CleanupFormattingGap`,
  `CleanupContextlessFormattingGap`, `CleanupFormatting`, `CleanupAfterTransaction`): no difference
  by reading, and byte-equal with Yjs on 4,206 unobserved steps with concurrent remote formats, plus
  4,381 observed steps once findings 1 and 2 are fixed.
- `YMap.Count`: equal to `size` on every type after every one of 4,253 steps.
- `Keys` for set twice, set then delete, delete then set then delete in one transaction (S11) and
  array `Changes.Delta` for insert and delete in one transaction (S12): equal.
- Surrogate pair split by an insert in the middle (S17): same text (U+FFFD on both sides) and bytes.
- `ApplyDelta` with `sanitize`, a retain beyond the end (newlines), prelim text operations (S21, T12),
  attribute inheritance of `Insert` and the explicit nulls of `InsertEmbed` (T11): same bytes.

## Not ported (what a Yjs user would miss)

- A shared type as text content: `insertEmbed(index, ytype)`, `applyDelta([{insert: ytype}])`
  (finding 10).
- `toDOM` on `YXmlFragment`, `YXmlElement`, `YXmlText`, `YXmlHook` (no DOM in .NET).
- A non-throwing `YMap` lookup (`get` returning `undefined`): `Get` throws; `TryTypeMapGet` is
  protected.
- `YTextEvent#changes` in its text form (finding 13).
- `toDelta()` on a text that is not in a document yet, and `clone()` of one (finding 15).
- `set` returning the value; `getTypeChildren`; `removeAllEventHandlerListeners`; the premature
  access warning.

## Not compared

- `UndoManager` together with events (`StackItemAdded`/`Popped` and their `ChangedParentTypes`
  copies) and with the formatting cleanup; only the `ToString` cache was run under undo/redo.
- XML types under random concurrent edits (they share the list, map and text code that was traced;
  only fixed scenarios S22, T6, T7, T15 were run).
- `ToDelta` with snapshots beyond one fixed scenario (T8): no traces with snapshots, formats that
  are visible in one snapshot only, or `computeYChange`.
- Subdocuments (`ContentDoc`) as array and map values, `ContentJson`, `ContentBinary` values, and
  which values `AnyEncoding.Validate` rejects that Yjs accepts (`Date`, `undefined`).
- Relative and absolute positions, the encoders and decoders, `Item.Integrate` (other areas).
- Negative indices, and indices beyond the length for `YText` (Yjs appends silently; read as equal).
- Markers on a root text that got formats as a placeholder (finding 19): read, not run.
